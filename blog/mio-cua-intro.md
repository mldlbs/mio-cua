# 👁️ 别给 AI 写接口，给它一双眼睛

> 一句话：过去我们给 AI 写接口，让软件能被 AI 调用；而现实是大多数软件根本没有接口。mio-cua 换了个思路——**不给软件写接口，给 AI 一双眼睛**，让它像人一样看着屏幕、自己操作，有界面就能干活。

---

## 🧠 过去的思路：给软件写接口

让 AI 操作软件，过去的做法是**写接口**：调 API、接 SDK、做插件。前提是软件肯开放接口。

但现实是：

| 系统类型 | 有开放接口？ | 有操作界面？ |
|------|:---:|:---:|
| 财务系统 / 政务平台 | 大多没有 | ✅ |
| 银行柜面 / 医院系统 | 基本没有 | ✅ |
| 制造业 ERP / 公司 OA | 大多没有 | ✅ |
| 桌面软件 / 老网站 | 通常没有 | ✅ |

这些系统没有接口，是因为它们本来就是为人设计的——**人看屏幕、做判断、点鼠标**，这就是人操作电脑的全部方式。

> 于是出现了断层：AI 进不了这些系统，因为它们没接口。但这个断层恰恰是"人日复一日重复操作"所在的地方——**每天点同样的按钮、录同样的数据、导同样的报表**。

---

## 👁️ 换一个思路：给 AI 一双眼睛

mio-cua 的核心主张：**有界面就能自动化**。不给软件写接口，而是模仿人操作电脑的完整方式：

| 环节 | 人怎么做的 | mio-cua 怎么做 |
|------|-----------|---------------|
| 看 | 眼睛扫屏幕 | 识别屏幕上的按钮、输入框、文字 |
| 想 | 大脑判断该点哪 | AI 分析界面，决定下一步动作 |
| 做 | 手点/输入/按键 | 真实操作鼠标键盘，每步截图留痕 |

**网页场景尤其能体现这个理念**：直接"看"页面上的按钮和链接就行，不需要浏览器插件、扩展，也不需要读网页源码——就像人打开网页直接操作一样。

---

## 🌍 格局：它不是小工具，是 AI 的操作层

把 mio-cua 放到更大的图景里看：

- **对 AI 生态**：任何 AI 客户端（Claude / Cursor / ChatGPT）接入 mio-cua，就获得了操作电脑桌面的能力。AI 的边界从"会调接口"扩展到"能操作任何软件"
- **对自动化行业**：传统 RPA（UIPath 等）要拖流程、配节点、写脚本，界面一改就崩。mio-cua 是**新一代 RPA**——你说一句"帮我做这件事"，AI 自己看着屏幕完成
- **对业务世界**：财务月结、政务办事、数据录入、客服操作、运维巡检——一切"人对着屏幕重复操作"的岗位，都可能被重新定义

> 以上是它的定位和方向，不是某个已落地的客户案例。判断一个工具的价值，要看它能在哪个层面被复用。

## ⚡ 怎么用

### 安装

```bash
pip install mio-cua
```

### 配置模型

```powershell
$env:OPENAI_API_KEY = "sk-xxx"
```

### 说一句话，AI 帮你干活

```bash
mio-cua run "读取 D:\报表\今日订单.csv 的金额列，算出合计，保存到 合计.txt"

mio-cua run "登录进销存系统，导出今日入库单" --dry-run  # 先看计划，不动手
```

### 接入你正在用的 AI

把 mio-cua 装成插件（MCP Server），Claude / Cursor / ChatGPT 就能直接操作你的桌面。
