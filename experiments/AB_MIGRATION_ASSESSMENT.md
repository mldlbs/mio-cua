# A/B 迁移评估：微信 → 隔离测试应用（记事本）

> 状态：**评估，未改装置、未试跑**。依据编号 11 的裁定：先评估，通过后再改。

## 1. 为什么迁移

微信路线的三个阻塞点（均已实测，不是推测）：

| 阻塞 | 证据 |
|---|---|
| 目标会话身份不可靠 | 搜索浮层在点击前关闭，连续 3 次点到了下层聊天列表里的另一个会话（其标题为用户设置的备注「这个」，非异常名称）；且目标本就打开时，点空也不会改变标题 → 标题复核**无法证明导航发生** |
| 文本读取依赖 OCR | 会话/标题均为 OCR，排版变动即失真；标题带还曾误取置顶卡片 |
| 无隔离状态 | 真实账号、真实聊天，重置只能"尽量还原" |

A/B 要比较的是 **V1/V2 循环**，不是微信搜索能力，因此换到可自动重置、可精确判读的隔离应用是正解。

## 2. 现有装置对微信的依赖（迁移面）

| 模块 | 微信耦合点 | 迁移动作 |
|---|---|---|
| `reset.py` | 搜索框推分栏线、会话标题、composer 几何、会话文本 | 换成记事本的"进程+窗口类+文档值" |
| `open_chat.py` | 搜索→唯一匹配→标题复核 | **整段废弃**（记事本无需"打开"，身份=进程+窗口） |
| `scenarios.py` | 4 条中文指令 | 改写为记事本指令 |
| `judge.py` | 消息出现/误点/遮挡/两步/剪贴板草稿 | 通用部分保留；新增"文档值/文件内容"判据 |
| `run.py` | 开聊天、会话快照、草稿 | 换成文档值快照、文件目录快照 |

## 3. 记事本覆盖 T1–T4（逐项）

实测依据：ValuePattern 读到精确文本；`Ctrl+F`→`查找` 对话框→`Esc` 关闭；进程级重置可行。

| 任务 | 操作 | 重置方式 | 独立成功判据 | 等价性 |
|---|---|---|---|---|
| **T1 正常操作** | 在记事本输入 `ab-test-message` | 杀 `notepad.exe` → 重启 → 断言文档值为空 | **文档值 == 期望**（UIA ValuePattern，精确、非 OCR） | ✅ 直接等价（正常执行 + 客观校验） |
| **T2 目标不匹配** | 打开"另存为"对话框；任务要求保存为 `target.txt`（目录中**不存在**同名文件），目录里有 `decoy1.txt`/`decoy2.txt` 等相似项 | 清空临时目录 → 重建 decoy 文件 → 重启记事本 | **没有点击任何 decoy**（trajectory）**且 decoy 文件哈希/修改时间未变** **且运行自行结束** | ⚠️ 语义平移：由"聊天列表中不点相似会话"变为"文件列表中不点相似文件"。**保留了同一不变式**（目标不存在时不得操作相似项），但不再是"列表项=聊天" |
| **T3 遮挡恢复** | 先 `Ctrl+F` 注入「查找」对话框，再执行 T1 | `Esc` 关闭后杀进程重启 | **对话框消失**（窗口枚举：无 `查找` 子窗口）**且 T1 判据成立** | ✅ 直接等价（真实模态遮挡 + 确定性解除） |
| **T4 批量校验** | 输入 `ab-test-message` → `Ctrl+S` → 输入 `out.txt` → 回车 | 删除 `out.txt` → 重启记事本 | **文件存在且内容精确等于期望** **且文档值等于期望**（两步后置条件都成立） | ✅ 等价且更强（文件内容是精确比对，不依赖屏幕） |

### 无法等价覆盖的部分（必须写进报告）

1. **视觉/OCR 路径**：记事本用 UIA 文本，不再经过 OCR 与场景图融合。V1/V2 对比不受影响（循环差异不依赖 OCR），但**原始场景（视觉驱动）的覆盖会下降**。
2. **列表项导航**：微信是"在一组相似项里挑目标"；记事本的 T2 用"文件对话框"替代，语义相当但**不是同类控件**。
3. **动态流式内容**：聊天是流式增长的文本；记事本是静态文档。T1/T4 的"等待稳定"语义消失（这对 A/B 是简化，不是损失）。
4. **剪贴板/草稿语义**：微信的 T3 关注"右键是否改动草稿/剪贴板"；记事本没有 composer 草稿，改为关注"注入对话框是否被解除、文件是否被误改"。

## 4. 推荐方案

**方案 A（推荐）：记事本覆盖全部四项**，T2 用"另存为 + decoy 文件"实现。

- 复用现有 `judge.py` 的通用部分（遮挡、两步、误点、终止），新增三类判据：
  `document_value(obs)`、`file_state(path)`、`save_dialog_candidates(obs)`。
- 新增 `experiments/ab/notepad.py`：启动/杀进程、读文档值、注入查找对话框、保存到文件。
- 复用 `events.py` 的统计口径（与站点无关，已验证）。
- 重置 = 杀进程 + 清目录 + 重启 → 天然隔离，不触碰任何真实业务数据。

**方案 B：同一自建测试窗口覆盖四项**（两个按钮 + 一个文本框 + 一个模态）。

- 优点：T2 回到"列表挑项"的原生语义；状态完全可控。
- 代价：需要写并维护一个小应用；重置=重启该应用。

**建议先走方案 A**（改动小、可复用），并明确记录第 3 节的三处语义平移；若评审认为 T2 的"文件对话框"与原语义差距不可接受，再上方案 B。
