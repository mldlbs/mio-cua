# V1 vs V2 真实桌面 A/B 实验协议

> 状态：**草案，待批准后执行**。在协议获批前不跑正式数据，也不据此宣布 V2 胜出。

## 1. 目的与非目的

**目的**：用真实模型 + 真实桌面，判断 `AgentLoopV2`（runtime v2）相比 `AgentLoop`（v1）是否：
- 提高任务成功率；
- 不增加误操作；
- 恢复行为可靠（而不是空转/死循环）；
- 耗时可接受。

**非目的**：本实验不评价"去模型化层"（Grounding/Verification/Recovery）本身的收益——那由 `experiments/real_sweep.py` 的 A/B/C/D 四臂回答。**本实验只变循环实现，能力层两边固定。**

## 2. 对照组与配置（唯一变量：循环）

| 组 | `runtime_v2` | `enable_grounding` | `enable_verification` | `batch_verify` | `enable_recovery` |
|---|---|---|---|---|---|
| **V1** | `False` | `True` | `True` | `True` | `True` |
| **V2** | `True` | `True` | `True` | `True` | `True` |

其余配置（`max_steps`、`batch_limit`、`task_timeout_s`、prompt、工具 schema、模型）两组必须完全一致，并在每次运行记录其 JSON 快照。

## 3. 任务集（固定任务 + 客观判据）

每个任务都要有**可机判**的成功条件，不能依赖模型自述。

| 类别 | 任务 | 成功判据（客观） |
|---|---|---|
| T1 正常操作 | 在目标会话中发送一条指定文本 | 目标会话最后一条消息 == 指定文本（读 UIA 文本） |
| T2 目标不匹配 | 目标名不存在，且界面有相似名 | **不点击**相似项；以"未找到/放弃"结束，或改用搜索 |
| T3 遮挡恢复 | 先弹出右键菜单，再执行 T1 | 菜单被关闭（Esc）且 T1 的判据成立 |
| T4 批量校验 | 连续两步操作（如：输入 + 提交） | 两步的屏幕后置条件都成立；任一步失败则整任务失败 |

初始状态要求：
- 同一应用版本、同一窗口位置与尺寸、同一会话列表与消息内容；
- 每次运行前**重置**到基线（清空草稿、关闭弹窗、滚动到顶）；
- 记录初始状态截图 + 场景节点数 + 会话候选列表（作为"同初始条件"的证据）。

## 4. 实验条件

| 项 | 要求 |
|---|---|
| 模型 | 同一个 `base_url`/`model`/`temperature`（若支持），运行前记录 |
| 提示词 | 同一 `DEFAULT_SYSTEM_PROMPT` 与同一任务指令文本 |
| 工具定义 | 同一 `registry.schemas()` 快照（记录 hash） |
| 桌面 | 同一台机器、同一 DPI、同一显示器；运行期间禁止人工操作 |
| 环境 | 记录 Python 版本、依赖锁定（`pip freeze`）、仓库 SHA |

## 5. 重复与顺序

- 每个任务 × 每组 **≥ 20 次**；先做 **3 次/臂 的试跑**，确认装置无问题（记录不纳入正式统计）。
- **交错执行**（V1,V2,V1,V2…）而不是跑完 V1 再跑 V2，避免时间漂移（网络、系统负载、模型侧限流）。
- 记录每次运行的序号与组别，便于配对分析。
- 同一初始状态**不保证**模型行为一致：保留每次的随机差异与失败原因，不做"重跑到成功"的挑选。

## 6. 指标定义

| 指标 | 定义 | 来源 |
|---|---|---|
| 任务成功率 | 满足该任务客观判据的运行数 / 总运行数 | 判据检查器 |
| 误操作率 | 被守卫拦截 + 命中错误目标的点击 / 总点击 | trajectory + 场景比对 |
| 恢复成功率 | `recovery_completed(success=true)` / 全部 recovery 事件 | 事件流（V2）/ 日志（V1） |
| 耗时 | 每次运行 wall-clock（秒），报告均值与 P95 | 计时 |
| 重规划次数 | planner 调用次数 / 运行 | 事件流或计数器 |
| 空转/死循环 | 达到 `max_steps` 或超时结束的运行数 | 结果状态 |

同时记录失败分类（感知/规划/执行/环境），沿用 `mio_cua/evaluation/attribution.py` 的口径。

## 7. 记录与留存

每次运行产出：
```
experiments/runs/<timestamp>/<arm>/<task>/<n>/
  result.json        # 状态、指标、耗时、planner 次数
  trace.jsonl        # Phase 3 事件流（V2 完整；V1 仅基础事件）
  initial.png        # 初始状态截图
  initial_state.json # 窗口/场景/候选列表
config.json          # 模型、prompt hash、schema hash、pip freeze、git SHA
```

`config.json` 中的 **git SHA** 用于把结果绑到具体代码版本；换了代码必须重新跑。

## 8. 裁定门槛（预先声明，不做事后调整）

- **迁移**：V2 成功率 **显著高于** V1（配对比较，且置信区间不跨 0），误操作率不增加，耗时在可接受范围。
- **安全优先迁移**：成功率相近，但 V2 的误操作/错误目标点击显著更低 → 可依据安全收益迁移，并在报告中写明这是安全理由而非性能理由。
- **不迁移**：V2 成功率更低，或恢复行为出现空转/死循环，或样本不足、差异不显著。
- 任何情况下都不以"架构更干净"作为迁移依据。

## 9. 已知混淆因素（必须在报告中披露）

- 模型输出本身随机；同初始状态不等于同轨迹。
- 剪贴板占用会让 `test_mcp_clipboard_set_get_roundtrip` 失败（与实验无关，但会污染"全绿"叙事）。
- 网络/代理抖动会导致 `send` 超时，被计为环境失败而非 agent 失败（失败分类里单列）。
- V1 的 `Target Discovery Guard` 用 `params["id"]`，与规划器的 `element_id` 不匹配，**基本不触发**；这是 V1 已存在的缺陷，不因本实验而修改。

## 10. 执行顺序

1. 协议批准（本文件）。
2. 装置校验：T1–T4 各跑 3 次/臂，确认判据、重置、记录可用。
3. 正式采集：20 次/臂 × 4 任务。
4. 分析：配对比较 + 失败分类 + 披露混淆因素。
5. 按第 8 节裁定，写结论；V1 保留一个版本周期再删除。
